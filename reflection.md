### Project Reflection

For this project, I built a customer support AI agent using Amazon Bedrock AgentCore and the Strands SDK. A key design decision was to use **AgentCore Gateway with MCP** to connect the agent to external customer-support tools. I separated read-only order operations behind an API Gateway target and refund operations behind a Lambda target. This allowed the agent to use a consistent MCP interface while keeping the underlying services independent. I also implemented AgentCore Memory so customer facts and preferences could be retrieved across sessions and incorporated into future conversations.

One of the main challenges was getting the AWS integrations and permissions configured correctly. The Knowledge Base initially could not be accessed because the runtime role did not have permission to call the Bedrock Retrieve API. I resolved this by adding the required `bedrock:Retrieve` permission for the specific Knowledge Base. The Code Interpreter also initially returned an access-denied error, so I added the required AgentCore Code Interpreter permissions to the runtime role. After these changes, the Knowledge Base and loyalty-discount calculation tests completed successfully. I also verified cross-session memory by storing a customer's name and communication preference in one session and successfully retrieving them in a separate session.

I encountered an additional deployment-specific issue with the AgentCore Browser. The browser worked when tested directly, but the deployed runtime packaged the Playwright Node executable without executable permissions. This caused a permission error and a subsequent timeout error when the browser was invoked. I diagnosed the issue by inspecting the deployment artifact and CloudWatch logs rather than changing the application logic unnecessarily.

For production, I would prioritize **security, cost, scalability, and observability**. IAM permissions should follow least privilege, such as granting the runtime access only to its required Knowledge Base and Code Interpreter resources. Gateway and Lambda operations should also validate customer and order authorization before performing sensitive actions such as refunds. CloudWatch monitoring should track invocation errors, latency, and tool failures, while memory and Code Interpreter usage should be controlled to manage operational costs as the number of customers grows.
